## 二、回退机制——没有任何静默失败

系统的设计原则是：缺译**可见且优雅**，绝不损坏：

- **界面文案：** `t(key, fallback)` 在键缺失时返回中文 fallback。你看到的是中文，而不是 `common.filter` 这样的裸键。
- **类别标签：** `ln(entry, fallback)` 英文态优先取 `entry.nameEn`，缺失回退 `entry.name`。
- **节点元数据：** `nt(node)` / `ns(node)` **按节点 id** 查 `EN_NODE_META`。任何没有匹配 id 的对象——成就、学习路径、词条——都原样返回自己的 `title` / `summary`。这正是全站批量接线安全的原因。
- **节点正文：** `loadNodeBodyBilingual(nodeId, lang)` 返回带 `isFallback` 标志的 `BilingualBodyResult`。英文不可用时，`DetailPanel` 渲染中文正文**并附一张明确的提示卡：「英文版尚未提供」**。

那张提示卡是有意为之的功能。**不要为了让覆盖率好看而删掉它。** 读者有权知道自己读的是回退内容。

**性能说明：** 英文词典**和** `EN_NODE_META` 都是动态 import。纯中文会话为 i18n 下载 **0 字节**额外内容，因此翻译覆盖率不影响首屏体积门禁。

### 3.2 组件 —— 137 个中 55 个干净

**82 个 `.tsx` 仍含硬编码中文。** 注意「含中文」不等于「未翻译」——其中一部分是注释、传给 `t()` 的 fallback 字面量（这是正确且必需的），或数据。但这个数字是剩余工作量的诚实上界。

**41 个组件中的 137 处标题/摘要渲染点已接线** `nt()` / `ns()`，节点标题与摘要在任何出现的位置都会以英文渲染。

### 3.3 节点元数据 —— 763 / 763

位于 `src/data/i18n/en-node-meta.ts`，每条含 `titleEn` 与 `summaryEn`，按时代分组。已校验与 `ALL_HISTORY_NODES_INDEX` **一一对应**：763 个 id，缺失 0、多余 0、含中文残留 0。

### 3.4 类别标签 —— 全部 23 个

`ERAS`（7）、`CATEGORIES`（6）、`CIVILIZATIONS`（10）均带 `nameEn`，统一经 `ln()` 消费。

## 四、已发现并修复的缺陷

这些是**真的在浏览器里把界面切到英文、读 DOM** 发现的，再回到代码确认。目前源码层面全部关闭；`npm test`、`npm run build`、`npm run test:gate` 均通过。

| 缺陷 | 根因 | 状态 |
|---|---|---|
| 时代名不翻译 | `ERAS[].nameEn` 早就有，但没有任何视图消费它 | **已修**，经 `ln()` |
| 分类名不翻译 | `CATEGORIES[].nameEn` 同样的接线断层 | **已修**，经 `ln()` |
| 文明名不翻译 | `CIVILIZATIONS` 的类型注解没有 `nameEn`，字段被类型拒绝 | **已修** —— 放宽类型并补 10 个英文名 |
| `html lang` 不更新 | 没有同步 `document.documentElement.lang` 的 effect | **已修**，在 `I18nProvider` 内 |
| **已译元数据从未渲染** | `useNodeI18n` / `getNodeTitleLang` 写好了却**没有任何组件调用**——连此前已译的节点也显示中文 | **已修** —— 137 处渲染点接线 |
| **英文态搜索失效** | 关键词表是中文，只拿译名匹配会让所有中文查询落空 | **已修**，经 `bilingualHaystack()`，始终中英双查 |

## 七、翻译规范

已确立且要求遵守：

- **专名：** 用通行英文译名。Qin Shi Huang、Mesopotamia、Ashurbanipal。不自创罗马化。
- **年代：** BCE / CE，带千分位，经 `src/i18n/format-year.ts`。不要手工格式化年份。
- **保真：** 翻译不得增加、删除或软化史实断言。中文若错，请提史实更正 issue——不要在英文里悄悄改掉。
- **神话按神话表述。** 传说人物一律作为传说呈现，绝不断言为有记载的史实。
- **文体：** 百科式、博物馆标签口吻。与中文一致。
- **不用 emoji。** 全站规则。
- **绝不破坏中文匹配。** 任何筛选、搜索或关键词表都必须用 `bilingualHaystack()`，不能只用译名。
- **绝不用汉字阈值硬切英文。** 用 `smartTrim()`。
