## 一、这个产品要解决什么问题

屏幕上读历史的主流方式，几乎都有同一个毛病：**把时间压成了一份清单。**

教科书给你章节，百科给你条目，视频给你叙事。三者都擅长深度，都不擅长**同时性**。它们没法让你一眼看出：

- 秦统一中国那年，地球上还在发生什么？
- 玛雅崩溃是在诺曼征服之前还是之后？
- 哪些文明在同一时刻处于巅峰——它们彼此知道吗？

这些不是冷知识。同时性是历史理解的骨架：正是它把"罗马帝国灭亡了"变成"罗马西半部碎裂的同时，东半部又延续了一千年，而那时唐帝国是这个星球上最大的政体"。

人类文明时间地图就是为了让这个结构**看得见、摸得着**。

## 二、它是什么

一座**纯展示型的交互历史图谱**。具体说：

- **763 个历史节点**，每个都有长文正文。不是词条占位——整个内容库有 261 万中文字。
- **同一份数据的四种视图。** 你看到的从来不是不同内容，而是同一批内容的不同透镜。
- **关联是一等数据。** 2,396 组唯一节点对，带类型、双向，所以"这个东西连着什么"是一次查询，不是一次猜测。
- **没有后端。** 全部内容是带类型的 TypeScript，整体编译成静态文件。

### 它刻意不做的事

| 不做 | 原因 |
|---|---|
| wiki | 没有编辑界面、没有账号、没有修订历史。内容即代码，靠 PR 评审。 |
| CMS | 没有数据库、没有后台。这让部署极简，也让内容有版本。 |
| 权威参考书 | 内容库是既有史学共识之上的 AI 辅助写作，详见[来源与灵感](SOURCES-AND-INSPIRATION.zh-CN.md)。 |
| 课程 | 有学习路径，但没有评分、没有班级、没有进度锁。 |

## 三、四种视图

### 3.1 时间轴——按顺序读

默认视图。一条竖向主脊配时代色带，节点以卡片形式挂在上面，显示年份、文明徽章、分类与摘要。

- **按时代分组**，时代标题吸顶，所以在 300 万年里你始终知道自己站在哪儿。
- **按文明、分类、时代、关键词筛**，条件可叠加。
- **点任意节点**打开详情面板读全文。
- **跳转导航**，不用一路滚过去就能换时代。

适合：第一次通读、按年代学习、"带我走一遍青铜时代"。

### 3.2 世界地图——按空间读

同一批节点，用 Leaflet 打在 **Esri 卫星影像**上，483 个定位标记。

- **自由拖拽缩放**，没有人为边界。可以放大到单个遗址，也可以拉到整个地球。
- **按时代过滤**，让地图一次只显示一个时期，而不是 300 万年糊在一起。
- **标记按文明着色**，带图例。
- **点标记**打开的详情面板与时间轴完全一致。

适合：理解地理作为原因。为什么两河与埃及都趴在大河上；为什么草原帝国长成那个样子；波利尼西亚人到底扩散到了多远。

> 需要联网。底图来自 Esri，适用其条款，详见[第三方素材声明](THIRD-PARTY-NOTICES.zh-CN.md)。

### 3.3 百科列表——按检索读

密集的可搜索列表。筛选条件与时间轴相同，但为扫视而非叙事流优化。

适合：查东西。"把中世纪、中东、带军事标签的全给我列出来。"

### 3.4 专题馆——跨时代读

策展式展览，**横切**时代而不是顺着时代走。每个专题有自己的数据集与版式：

| 专题 | 干什么 |
|---|---|
| **帝国** | 主要政体的兴衰跨度，放在同一根轴上比 |
| **帝国对比** | 选定帝国的结构性并排对比 |
| **城市史** | 单个城市贯穿其全部存在的轨迹 |
| **日常生活** | 各时期普通人吃什么、穿什么、干什么、怕什么 |
| **术语表** | 名词、概念与词汇的释义 |
| **学习路径** | 贯穿内容库的有序阅读路线 |
| **测验与成就** | 自测，含简答题型，配成就系统 |

适合：主题式学习，以及从年代的暴政里挣脱出来。

## 四、招牌功能

### 4.1 历史放映机

全屏演示模式。年份游标从**公元前 300 万年**推进到至今，推进过程中：

- 地图显示那一刻存在的东西；
- 事件日志与游标同步累积重要事件；
- 可暂停、拖动、加速、重置。

以下约束是**测试焊死的**，不是"设计上打算这样"：

- 地图**锁定跟随播放**，用户拖动不可能让它与游标失步。
- 事件流与年份读数**纯派生自 `currentYear`**。没有离场动画层能在重置后把旧事件留在屏幕上。
- 每个控件热区 **≥44×44 px**，手机上够得着。
- 弹层 portal 到 `document.body`，任何祖先 transform 都无法困住它或延迟它的可交互时间。

适合：教学、录屏，以及单纯地看着 300 万年流过去的那点快乐。

### 4.2 五套主题，五种阅读环境

这不是换配色。每套都是一种刻意设计的阅读语境，且每套都做过对比度实测：

| 主题 | 性格 | 适用 |
|---|---|---|
| **博物馆** | 深色木质展柜、暖金 | 默认。夜间阅读，展览感 |
| **墨夜** | OLED 黑金 | 夜晚、OLED 屏、最高对比 |
| **羊皮纸** | 暖调陈纸 | 长文阅读，日光下护眼 |
| **宣纸** | 素白宣纸 | 最干净的长读，接近印刷 |
| **竹简** | 青墨绿汉简 | 古典中式审美 |

五套全部在细线、焦点环与顶栏边框上达到 **WCAG 3:1**——用 alpha 合成算出来的，不是拿眼睛估的。

### 4.3 竖排古籍阅读

面向中文内容的从右至左、从上到下竖排模式，仿线装书。这是真正的版式模式，不是 CSS 旋转把戏。

### 4.4 文明泳道

平行的横向泳道，一条一个文明，共用一根时间轴。这是对第一节那个同时性问题最直接的回答：你能看见十个文明同时在呼吸。

### 4.5 双语界面

中英可切，入口在顶栏，按浏览器持久化。英文内容在尚无译文处**带明确的界面提示**回退中文。

> **覆盖尚不完整。** 精确数字见[翻译进度](TRANSLATION-STATUS.zh-CN.md)。

## 五、给谁用

- **学生**——先要一个时期的形状，细节才挂得住。
- **老师**——想要放映机和地图，而不是又一叠幻灯片。
- **写作者与游戏设计者**——做时代考据，需要快速的跨文明上下文。
- **普通好奇的人**——内容库是写来读的，不是写来索引的。
- **开发者**——想要一份有真实体积门禁、测试扎实的 React + Vite 工程来研究或 fork。

## 七、产品原则

1. **结构先于细节。** 每个视图的存在都是为了揭示一种关系，不是为了展示一条记录。
2. **不静默失败。** 缺译文、分片加载失败、构建产物读不到——每一种都要显形并被处理，绝不糊过去。
3. **性能是带测试的功能。** 不被 CI 强制的首屏预算只是一个愿望。我们的会让构建失败。
4. **对来源诚实。** 内容库明说自己是 AI 辅助写作、可能有错。一个隐藏来源的历史产品比没用更糟。
5. **够得着。** 44px 热区、键盘可导航菜单、实测对比度、移动底部 Tab。无障碍是验过的，不是声称的。

## 八、当前局限

直说，因为只列优点的产品页那是营销：

- **英文不完整。** 界面部分已译；133/763 节点有英文元数据；15/763 节点有英文正文。其余带提示回退中文。
- **AI 辅助内容库。** 遵循主流共识，但未经同行评议，可能有错。不要当权威引用。
- **地图需要联网。** 没有离线瓦片。
- **没有同步。** 阅读位置、主题、语言只存在当前浏览器。
- **没有账号、评论、批注。** 这是设计选择。
